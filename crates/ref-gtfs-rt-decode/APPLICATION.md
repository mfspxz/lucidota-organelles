# Applying `ref-gtfs-rt-decode` — the translink-repeater port (TRN)

The sole consumer today is the translink-repeater worker
(`~/workspace/translink-repeater/`): a JS worker that polls
TransLink's GTFS-RT V3 feeds, decodes them with `gtfsrt.js`,
snapshots the JSON into KV, and serves `/v1/vehicles|trips|alerts`
with route + bbox filters. This organelle (org-036, GAP-21) is
the decoder half of its Rust port. The shell half is org-031
(`ref-edge-worker-shell`), whose APPLICATION.md specifies TRN's
shell adoption; the honest order is decoder first — a Rust shell
cannot call the JS decoder — and this crate is that first step,
parity-proven against the JS on live feed bytes
(`tests/parity.rs`, goldens generated by `gtfsrt.js` itself).

## Using the decoder directly (any Rust consumer)

```toml
[dependencies]
ref-gtfs-rt-decode = {
  path = "<relative path>/organelles/crates/ref-gtfs-rt-decode",
  default-features = false, # pure decoder only: std-only, no host/manifest deps
}
```

```rust
let feed = ref_gtfs_rt_decode::decode_vehicles(&bytes)?;
let json = feed.to_json(); // byte-identical to JSON.stringify of the JS result
```

Drop `default-features = false` to also get the Organelle trait
surface (ops `decode_vehicles` / `decode_trips` / `decode_alerts`,
input `{"bytes_hex": "..."}`).

## Port sequence for the repeater worker

1. **Decoder (this crate) — DONE.** org-036 built and verified:
   21/21 parity cases byte-identical (3 live MBTA snapshots +
   synthetic edge feeds + malformed inputs, × 3 decoders),
   wasm32 check PASS. Nothing in the incumbent worker changes
   in this step.
2. **Worker crate on the org-031 shell.** New crate with
   `features = ["workers"]`; routes `GET /health`,
   `GET /v1/vehicles`, `GET /v1/trips`, `GET /v1/alerts`.
   Handlers call this crate's pure API in-process
   (`default-features = false`); the shell supplies routing and
   the entry points, nothing else.
3. **Freshness stays in the handlers — it was never the
   decoder's.** The decoder emits `feed_ts` (it is in the feed)
   and the item arrays. `fetched_at`, `age_s`, `served_at`,
   `stale`, and `count` are computed by the handlers exactly as
   `worker-main.js` computes them today; the client contract
   (all five fields on every response) is preserved by the
   handlers, not renegotiated.
4. **Snapshots stay in the same KV namespace** (binding `SNAP`,
   org-027 via `Ctx::kv`), same keys (`snap:vehicles` etc.), so
   a cutover worker reads the incumbent's snapshots and vice
   versa during rollback.
5. **Upstream fetch + refresh floor.** Fetch via org-026
   (`ref-https-transport`); the 5 s refresh floor
   (`REFRESH_MS`) and the single-flight refresh become caller
   configuration on org-032 (`ref-breaker-quota`) — the floor
   is a limit-1 quota per feed, per GAP-01/GAP-06 — never a
   constant baked into the ported worker.
6. **Filters stay handler-side.** The `route` filter is a set
   membership test on decoded items; the `bbox` filter is
   ref-geo-point territory (point/bounds exist there) applied
   to decoded items. Neither belongs in the decoder.
7. **The secret does not move.** `TRANSLINK_API_KEY` stays a
   dashboard-set Worker secret, read from env by the ported
   worker exactly as the incumbent reads it; its placement is
   Zack-gated and unchanged by this port. (The incumbent is
   currently unkeyed — it answers `key_not_configured` — so the
   port can be built and staging-proven without waiting on the
   secret, and the secret remains the only cutover input.)
8. **Cutover gate.** Deploy the ported worker to staging,
   point both workers at the same upstream window, and diff
   `/v1/*` responses byte for byte (decoder output is already
   parity-proven; the diff exercises fetch, snapshot, and
   filter glue). The JS worker stays live and untouched until
   the diff is clean; rollback is re-pointing at it, with the
   shared KV snapshots valid for both.

## What this crate deliberately does not do

No fetching, no caching, no freshness stamps, no filtering —
those are GAP-01/GAP-02/GAP-06/GAP-07 concerns composed by the
worker. The decoder is a pure function of feed bytes, and its
only promise is that the function is the same one `gtfsrt.js`
has been running in production.
